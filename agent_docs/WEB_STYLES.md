# Websites and Web Interfaces

Use this guide with the shared writing rules in [AGENTS.md](../AGENTS.md). Follow the project's design system, existing components, and content requirements when provided.

## Content and layout

- Build the page around the visitor's main task. Put the information or action needed for that task where the visitor can find it easily.
- Write specific headings and labels. Use action text like “Download report” when it describes the actual result. Remove vague taglines, filler badges, repeated claims, and empty feature sections.
- Use sample data only when it serves the task, and label it clearly. Use real testimonials, statistics, logos, or ratings only when supplied or verified.
- Use spacing, alignment, typography, and contrast to show what belongs together. Use cards for content that benefits from grouping. Use gradients, shadows, badges, and animation only when they serve the design.
- Use relevant photos, screenshots, or diagrams when they help a visitor understand the page. Keep text readable over images and provide meaningful alt text for informative images.

## Behaviour and review

- Use semantic HTML and the appropriate native controls for links, buttons, and forms. Label fields, support keyboard use, and keep focus visible.
- Connect visible controls to their intended actions. For flows that need them, show clear loading, empty, success, and error states. Explain how to recover from an error.
- Check the main user flow on narrow and wide screens and with a keyboard. Check for horizontal overflow, unreadable text, clipped content, and broken links or controls.
- Review the page copy before delivery. Keep each piece of text that helps the visitor understand, navigate, or act, or fulfils a content requirement.
