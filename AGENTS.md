# Project Style Guide

Use these defaults for work in this project. Follow the user's instructions, assignment brief, or required template when they set a different requirement. Read the relevant guide in `agent_docs/` before drafting or editing.

## Shared writing style

- Use clear English at roughly MUET Band 4 level for explanations, documentation, and user-facing text. Use familiar words and direct sentences. Keep correct technical terms and explain them when the intended reader may need help.
- Match the tone to the reader and purpose. Use an academic tone for assignments and plain, practical wording for instructions, comments, and interface labels.
- Start with the answer, result, or next action the reader needs. Remove generic introductions, filler headings, repeated summaries, and claims that could apply to any topic.
- Prefer concrete details, worked examples, or evidence where they help. Keep dates, figures, names, and references accurate. Identify assumptions or gaps that affect the result.
- Avoid em dashes in original writing. Preserve exact quotations, names, identifiers, and text the user asks to keep verbatim.
- When editing existing work, preserve its meaning, terminology, and voice. Limit changes to the task.

Apply guides by deliverable or component. For example, use the Python guide for a site's Python backend and the web guide for its interface. Use the learning guide for a study handout's content and the document guide for its Word formatting. When exporting slides as a PDF, keep the slide layout and follow the learning guide.

Before delivery, check the result against the request, the relevant guide, and any supplied example or template.
